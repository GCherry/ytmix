3. Smart Video Rendering Architecture (Why It Renders Fast)

        The active path highlights based on your flag selection above
      


      

        
        

          

            Path A
            ~5 Sec / Hour
          

          
Video Loop + No Overlays

          

            Pre-transcodes the short 5–10s `.mp4` loop once to `1920x1080 yuv420p`, then muxes it with `-stream_loop -1` and `-c:v copy`. Zero frame re-encoding across the entire mix.
          

          

            
• Input: .mp4 / .mov / .gif

            
• Overlays: Disabled

            
• Video Codec: -c:v copy

          

        


        
        

          

            Path B
            HW Accelerated
          

          
Video Loop + Burned Titles

          

            Generates a dynamic `.ass` subtitle script with fade tags (`\fad(500,500)`) and burns it over the looping video using `h264_videotoolbox` (macOS) or `h264_nvenc` (Windows).
          

          

            
• Input: .mp4 / .mov / .gif

            
• Overlays: Enabled (.ASS Filter)

            
• Video Codec: videotoolbox / nvenc

          

        


        
        

          

            Path C
            Low-FPS Still Tune
          

          
Static Artwork Mode

          

            Uses `-loop 1 -tune stillimage` at `2 fps` (or `10 fps` when burning `.ass` track overlays) so `libx264` processes 93% fewer frames than a standard 30fps timeline.
          

          

            
• Input: .png / .jpg / .webp

            
• Framerate: 2 fps (or 10 fps w/ text)

            
• Video Codec: libx264 -tune stillimage
